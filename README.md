# 口述史馆 · 检索字幕

为口述史馆的单期访谈维护「检索字幕」。访谈按段转写，交回的 WebVTT 各用段内时码；
首页按原片顺序上传 2～12 份分段转写，填各段原片起止毫秒并选剪辑 CSV，系统在相邻段
重叠区内按同文字幕自动接通全期，预览确认后建立草稿，再逐次校订被剪口截断的字幕，
发布后按版号下载完整 WebVTT。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>。数据库保存在名为 `oral-history-data` 的卷里，
重启容器后已发布版本仍可原样下载。

本地开发：

```bash
python3 -m pip install -r requirements.txt
ORAL_HISTORY_DB=./data/oral_history.db flask --app app.wsgi run --debug
```

## 使用流程

1. **上传分段转写**：在首页按原片顺序添加 2～12 段，每段选一份段内时码 WebVTT，
   填写该段在原片上的起止毫秒，并选择一份剪辑 CSV。
   - 各段起点、终点都须逐段递增，相邻段必须有重叠。
   - 段内字幕只允许纯文本，按时码排列，不重叠也不越界。
2. **自动拼接与预览**：相邻两段以重叠区内**完整出现的同文字幕**交接，换算到原片后
   起点、终点偏差各不超过 **250 毫秒**。系统在所有能接通全期的方案里，取各交接
   起止绝对偏差之和最小的一组；预览页逐处显示采用的交接字幕、两边时码与偏差，
   以及合成稿的原片时码和合成 WebVTT。
   - 前段保留交接字幕，后段从对应字幕的下一条接起，拼后字幕不倒序、不重叠。
   - 同一中间段，接入所用字幕排在交出所用字幕之前。
   - **无解或最优并列**时标出有问题的分段，不建立新草稿，当前草稿原样保留。
3. **确认建稿**：确认后用这份合成字幕与剪辑表建立新草稿，重新校订剪口。
   - 预览后若草稿被更换或已发布，确认时会提示重新预览（HTTP 409）。
   - 写入失败时保留现有草稿。
4. **校订与发布**：整条落在片段内的字幕沿用正文；被剪口截断的字幕逐次录入保留
   文字或标为删除，全部处理完才能发布，发布后按版号下载完整 WebVTT。

剪辑 CSV 列：`片段号,原片起毫秒,原片止毫秒`（也接受 `fragment_no,start_ms,end_ms`；
无表头时按此顺序读取）。行序即拼接顺序；片段号在表内唯一；同一原片时段允许被多个
片段号重复取用。

## 规则要点

- **交接容差**：同文字幕须在两段中都完整落在重叠区内，换算到原片后起点、终点
  绝对偏差各不超过 250 毫秒。
- **最优方案**：在能接通全期的方案中，最小化各交接「起点偏差绝对值 + 终点偏差
  绝对值」之和；出现并列或无解时标出涉及的分段并保留当前草稿。
- **校订沿用**：仅当「片段号 + 原字幕正文 + 保留的原片范围」三者完全一致时，
  才沿用上一版校订；剪辑表或原片范围一变即需重新录入。
- **旧页面拒绝**：更换草稿或发布成功后，先前打开的草稿页提交校订/发布会被拒绝
  （HTTP 409），提示刷新后重新录入。
- **发布原子性**：有未处理剪口、版本冲突或写入失败时不会产生新版本；已发布版本
  存在 SQLite 中，重启后按版号原样下载。

## 项目结构

```
app/stitch.py       分段拼接：段内校验、重叠区交接候选、动态规划求最优、合成
app/core.py         领域逻辑：时码、WebVTT、剪辑 CSV、出现计算、校订继承、SQLite
app/app.py          Flask 路由
app/templates/      页面模板（含拼接预览与问题分段页）
app/static/style.css
tests/              单元测试与网页流程测试
examples/           三段示例转写与剪辑 CSV
```
